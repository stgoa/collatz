Independent review of the node [`README.md`](README.md) (legacy R61-b, status `written`, authored by the ChatGPT main lane). The authors' feeds were used for context only. Every number below comes from something I ran or from the node's own text.

## What I checked

- **Reading.** The node; `twelve-family-rho-dispatcher` (R57-b, reviewed) and the shared validator and closure compiler of `critical-image-rank-composition` (R43, reviewed; `rank_closure.py`: `validate_step`, `close_plan`, `compile_plan`); the claims and `one_step` entry points of the three added rules, `rank-excess-absorption-classification` (R58, `exact_bound.py`), `deferred-original-rank-testing` (R59, `deferred_rank.py`, read in full) and `maximal-inverse-cycle-continuation` (R60, `cycle_inverse.py`); the definitions in `elementary-bridge-quotient-normal-form` and `critical-nine-elimination`; the legacy dispatcher [`refined_rules.py`](refined_rules.py), its checker [`check_refined_rules.py`](check_refined_rules.py) and the certificate [`check_legacy_replay.py`](check_legacy_replay.py).
- **Statement 1 (priority) against the code.** `one_step` calls `OLD.one_step` (the unmodified `selected_rules.py` of the twelve-family node) and returns its plan after `RANK.validate_step`; otherwise it tries R58, R59, R60 in that order and returns the first non-`None` candidate, validated, tagged with the rule name and `ρ(w)`. R58's `one_step` is `None` off `w ≡ 437 (mod 512)` and returns `fifth_plan(w)` only when its status is `descending`, i.e. on the proved subdomain of R58's Statement 2. R59's `one_step` runs `defer` on each prescribed candidate with the module default `max_nodes = 10000`, returns only a `descending` result, and `defer` resolves high-rank requests exclusively with `OLD.one_step` of `selected_rules.py` (the module loads that file directly and contains no reference to the refined, R58 or R60 modules); a cap yields status `capped`, which is never accepted. R60's `one_step` is `None` unless eligible and `descending`. The `σ` rules are not imported anywhere in these modules.
- **Statement 2 (one step).** `validate_step` requires `w ∈ W5`, nonzero integer coefficients on W5 indices, `ρ(u) < ρ(w)` for every request and `div J = P(w) − Σ c(u) P(u)` exactly; it is applied to inherited plans too.
- **Statement 3 (closure, compilation).** `close_plan` is a memoised recursion: an unrecognised input contributes `{u: 1}`, coefficients are multiplied along the route and combined by linearity, a node cap raises `RuntimeError`; the final boundary is re-asserted. Termination: `ρ` is a positive integer, strictly smaller on every accepted edge, and each plan has finite support, so the substitution tree is finite (strong induction on `ρ`, as in R43). `compile_plan` is R40's `compile_five_plan`, which checks each supplied current's boundary and rejects missing or wrong input.

- **Certificate** (`python3 tools/run_certificates.py --node fifteen-family-rho-dispatcher`): `check_legacy_replay.py` PASS, exit 0, 9 s (replays `check_refined_rules.py` in the legacy layout against `refined_rules_audit.json`); the repository was unchanged afterwards.
- **Controls.** There is no `3x+d` analogue of the statement: the node composes conditional plans for `3x+1` with the killed atom `[1] = 0` and certifies nothing without supplied inputs, so the actual cycles of `3x+5` (minima 1, 5, 19, 23, 187, 347 from odd seeds `≤ 5000`) and `3x+13` (minima 1, 13, 131, 211, 227, 251, 259, 283, 287, 319) cannot refute it. The termination argument (strict decrease of a positive integer rank) is `d`-independent and an analogue would terminate equally well while supplying nothing; the `3x+1`-specific hypothesis is absorption at 1, which the controls fail (the analogous critical plan's seeds decrease only while `q > d` and end in states `≤ d`, which contain actual cycles).

## Findings

1. (imprecision) `one_step` raises `ValueError` for inputs outside `W5` (or non-positive) rather than returning `None`; the claim's "returns None or an integer current" describes `W5` inputs. No change needed.
2. (imprecision) R59 has several internal candidates (R55 first and second block, two R56 rays, R57 exit), each run through `defer` with its own 10000-node cap; a capped candidate is dropped and the next candidate is tried before the dispatcher moves on to R60. The node's "the dispatcher may then try R60" is correct but compresses this.
3. (information, not a defect) On the 1024-input window the full fifteen-family closure ends with no leaf for 180 of the 747 accepted inputs; the node reports only the side lane's size-stable figure of about 5.5% at random sizes. Neither is a coverage statement.
