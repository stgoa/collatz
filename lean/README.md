# Lean: the formal development

This folder holds machine-checked (Lean 4 + Mathlib) versions of results stated in prose elsewhere in the repository. A result marked `formal` has its statement here, a build receipt, and a `#print axioms` receipt showing only the standard axioms `propext`, `Classical.choice` and `Quot.sound`.

**[`STATE.md`](STATE.md) is the authoritative unit table.** For every formalised statement it records:
- its prose source;
- how the Lean statement matches it, including any extra hypotheses;
- its status, axioms and receipts.

[`LOG.md`](LOG.md) is the lane's journal, newest first.

## Build

Toolchain: `leanprover/lean4:v4.35.0-rc2` ([`lean-toolchain`](lean-toolchain)). Mathlib is pinned at `065356127b1dc0016f66b7283ce0ce2c4055aa55` in [`lakefile.toml`](lakefile.toml).

```sh
# install elan (https://github.com/leanprover/elan) once, then:
cd lean
lake exe cache get                     # fetch prebuilt Mathlib for the pinned commit
lake env lean CycleSpectrum.lean       # compile one file; repeat for the others
```

The two `*_Assembly.lean` files are regenerated by their `build_*.sh` scripts before compiling.

The committed receipts were produced in a Linux container with the same toolchain and Mathlib, as described in [`STATE.md`](STATE.md) under "Toolchain": the file was copied into a Mathlib-equipped project and compiled with `lake env lean`.

Receipts written before the 2026-10-19 restructure name the old path `experiments/lean_lane/…`. Their source hashes still match the files here.

## Receipts

For each compiled file, [`receipts/`](receipts/) holds:
- `<File>.build.txt`: the build exit status, the source sha256, the toolchain and the build time;
- `<File>.axioms.txt`: one `#print axioms` line per declaration, headed by the source sha256;
- `<File>.sha256.txt`: the source hash.

To check a receipt without building, compare `shasum -a 256 <File>.lean` with the receipt. Then scan the source for `sorry`, `admit`, `native_decide`, `axiom`, `unsafe`, `implemented_by`, `extern` and `opaque`.

## Contributing Lean

Follow [`AGENTS.md`](../AGENTS.md) §3 and the formalisation playbook in [`CONTRIBUTING.md`](../CONTRIBUTING.md):
- use the standard axioms only;
- commit the receipts with the source;
- add a row to `STATE.md` with the exact statement match.

A new development may be a new file in this folder. Keep `CycleSpectrum.lean` append-only, or split it into modules in a dedicated PR.
